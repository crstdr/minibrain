# Shared-writer contract module

Adopt this module into the local authoritative instructions only when independent writers may overlap. It supplements the [core contract](instructions.md); read-only helpers are not independent writers. Keep others read-only during installation or protocol changes, and have every writer load the resulting local rules before overlap.

- **Seats, not sessions.** Stable user-assigned seats/scopes live in one canonical ownership record read at startup. Session IDs are dated hints, not grants. A replacement keeps its seat but not its predecessor's lock, and stays read-only until predecessor/helpers have stopped or the user resolves the handoff. A seat never authorises simultaneous sessions.
- **Scope is explicit.** An unassigned session reads/reports only. Only the user assigns or reassigns areas; sessions may record user assignments made in that session. Peer messages cannot approve another writer's actions. Non-memory work may use disjoint whole-file assignments: edit only assigned files; crossing another seat's boundary requires agreement with that owner within existing user authority, or user reassignment. Work spanning areas belongs to all relevant seats; consult their canonical sources before closing or merging it. Capacity pressure is no exemption.
- **Protect the full shared transaction.** Cover shared-memory edits and every shared Git index mutation through post-commit verification. Assigned disjoint work files may be edited outside the memory lock, not outside their assignment. Every commit still coordinates the shared index. Work-only commits need no fabricated memory outcome. A Markdown claim is not an atomic lock; keep one writer until adequate coordination exists.
- **Retain attribution.** Shared checkpoint history identifies the responsible seat durably, independently of transient lock metadata or a shared Git account. The Git reference uses seat-prefixed commit subjects.
- **Acquisition proof, not a seat-name claim.** In the cooperative-lock implementation, acquisition is atomic and persistent across crashes with a fresh label per acquisition. Only the acquiring session releases it with its issued label. Seat name, age, timestamp or version cannot establish ownership. Require an empty Git index at acquisition; report existing staging rather than unstaging or committing it. Verify success before dependent edits or commands, and reread edited sources after acquisition.
- **Consistent reads.** Unknown change signals are unreliable. Compare signals covering in-flight edits, not only HEAD, before/after relevant reads and before action; reread after possible interference. Take a brief protected snapshot if needed, releasing before waiting. Keep the protection through the checkpoint's post-save check, but never while waiting on a person or agent.
- **Contention is not abandonment.** A foreign lock means no shared edits/staging: continue independent read-only work and recheck at an appropriate later point. If it remains held and blocks required work, report owner, acquisition time and unfinished state; an unreadable owner or unsafe state warrants reporting immediately. Do not set up automatic retry loops. Silence, age, a clean tree or an approval wait proves neither abandonment nor liveness. Only the user resolves ambiguous unfinished work before forced release. No inferred takeover, expiry, leases or automatic reassignment.
- **Preserve unfinished work.** Release only this session's acquisition after successful verification. On interruption or failure, preserve and report the incomplete checkpoint and its owner; never present it as a clean handoff. Cooperation cannot protect against a writer ignoring the protocol.
