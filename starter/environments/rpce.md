# Optional RPCE environment binding

Use this only for a brain actually working with RepoPrompt CE tools. The block is a small behavioural bridge, not an API manual or a required part of every brain.

At adoption, compare with the host's current injected guidance and omit redundant nudges. Put the useful block with environment bindings in the authoritative local instructions, leaving `<before_you_act>` first and separate. Do not add another full-contract loader or propagate it into every nested instruction file. Record any local adaptation. Mechanics, availability and permissions come from current tool/host guidance and the user's applicable instructions, not this example.

```text
<rpce_tooling_guidance>
Use an available Oracle for consequential uncertainty; choose workflows and authorised delegation when they simplify the work. Keep simple work direct.
1. Give collaborators the outcome, scope, authority and expected evidence. Do not assume they received this brain's memory or rules; share only permitted context.
2. Verify consequential findings and save durable outcomes in canonical memory, not only chats or exports. Review agreement does not expand authority.
3. For CAPACITY, save durable state and use self_compact at a safe boundary when needed.
Follow live RPCE guidance for tool mechanics and permissions.
</rpce_tooling_guidance>
```

A tool call, review verdict or saved rule is not proof of better behaviour. If a named tool is absent, adapt the binding to a permitted equivalent or record the limitation; do not invent access or route around a refusal. Share only context authorised for the actual recipient/provider, especially when review material leaves the local environment.
