# Installation acceptance, not a leaderboard

These preserve the original A1–A7 properties. Adapt the mechanism, not the property. This is ordinary installation verification, not a comparative evaluation campaign. Record implementation, host and conditions; a documented rule is not a pass.

Inject faults only into disposable synthetic copies, never a real person's brain. A1/A7 require a session that did not perform the setup/change and has no original chat history. A compaction or fork containing expected answers is not that check. Without such a session, report **not run**.

| Check | Required observation | Git/Markdown procedure |
|---|---|---|
| **A1: action-ready start** | Files-only purpose/current work, all human-waiting threads, next action or exact decision, within the local budget | Run installed resume; compare against source records, not only the index |
| **A2: current vs history** | Current state distinct; dated supersession; history cannot masquerade as current instruction | Inspect topic status and newest-first history directly; minibrain.py does not enforce their order |
| **A3: discovery** | Knowledge findable without its cockpit entry; origin/change traceable | Find a thread fact through MAP.md, then its outcome/history |
| **A4: evidence/focus** | Evidence dates not save dates; sourced goal, labelled inference and honest unknowns | Compare every live thread and Focus with dated sources; a checker cannot prove truth |
| **A5: coherent persistence** | Related knowledge, navigation/index and outcome persist together; partial updates exposed | In a disposable committed copy stage a topic without CHANGELOG.md: `check --staged` fails. Also leave a linked topic untracked or its MAP entry unstaged: prospective-commit validation must fail despite a valid working-tree view. Stage the complete real update, check and commit once; inspect the saved commit. The checker establishes structure, not meaningful outcome content |
| **A6: structural drift** | Broken references, duplicate navigation and budget overflow detected | In a clean disposable copy add [[Nowhere]] and a thirteenth thread: check names both. Use equivalent faults for other layouts |
| **A7: unfinished work** | A fresh session reports/preserves another writer's incomplete update, without sweeping it into its commit or discarding it | Leave a topic edit uncommitted in a clone; another session resumes. Verify no commit/reset/stash/discard |

For non-Git implementations, declare the A5/A7 mechanism and test. File readback alone does not prove transactions or recovery. A6 numbers/headings belong only to the reference; other budgets get their corresponding boundary tests.

## Additional use-driven checks

- Test the final integrated contract, with real bindings and without copied installer examples—not an intermediate template. Its operating and maintenance rules must work without the distribution checkout.
- A fresh reader can find the adopted source/revision and local adaptations without the installation chat. For an upgrade, demonstrate that a local adaptation and its reason survive source comparison, or explicitly record the approved change. Unknown provenance stays unknown; a version label is not proof of tested adoption.
- If an environment binding is installed, confirm the actual tools/loading path, omit local bindings that duplicate host-injected guidance and retain one authoritative copy of the useful local binding. Unsupported tools or host behaviour are reported, not treated as a successful integration.
- For an adopted operating gate, verify its complete block is first in every applicable AGENTS.md / CLAUDE.md, before titles/imports, and mirrors match the declared local authoritative copy: compare each complete opening-to-closing tag span, not just the labels. Preserve other instructions and record any deliberate placement/wording adaptation. Verify the actual host loading path, including explicit startup reads when needed; do not load the full contract twice. Report any duplicate gate exposure and unverified host behaviour. File inspection alone is not a loading/compliance test.
- Observe the gate through task outcomes, not recital: connection to the user's goal, grounded action, proportionate handling of recurring friction, and safe preservation of continuity before compaction. Check for added ceremony or unnecessary work too. Do not ask for private reasoning or infer effectiveness from a checklist in a reply. Comparative benefit requires a controlled with/without evaluation; this installation check does not establish it.
- A narrative deferred decision becomes actionable with decision-maker and reopening condition.
- A durable lesson is found/applied before the first relevant action after restart.
- A superseding instruction retains scope: valid conditional permission enables progress when conditions hold and prevents the prohibited branch otherwise.
- With multiple writers, the agent honours refused acquisition and unknown ownership. See [shared-writer checks](#shared-writers); helper tests alone are insufficient.

Record **pass / fail / not run / adapted with observed equivalent** per check. Exercise applicable checks successfully before claiming full acceptance. Reduced verification stays visible; useful partial operation is not universal validation.

## Shared writers

Before real overlap, verify user-assigned names/scopes, the local coordination bindings and that every writer loaded the instructions. On disposable data:

- Check contention, same-name replacement, wrong-label release, a nonempty index and lock persistence after the acquiring process exits.
- Verify that the agent stops on refused acquisition—not only that the helper refuses.
- Verify refusal of out-of-scope edits, cross-area closure using all owners' sources, and writer attribution on saved changes.

Helper tests alone do not establish agent cooperation. Keep one writer if dependable ownership/change signals or cooperation are unavailable.

## Principles and reflection

- In a fresh session without the setup conversation or distribution checkout, locate the active principles, maintenance instruction and reflection procedure through the installed entrypoint.
- Exercise the installation's bound mechanism: supported skill discovery **or** an explicit local read. Distribution evaluation should cover both alternatives separately; an installation need not create a second procedure to test the other path. Verify actual loading rather than assuming discovery from the filename.
- Verify the bound reflection procedure is included in the actual persistence/backup policy and remains available after a fresh start. For the Git reference, after saving, check that its real local path is committed (`git cat-file -e HEAD:<path>`) and not ignored (`git check-ignore --no-index -- <path>` returns 1, meaning no match). Unexpected errors are not a pass; the Markdown helper does not cover hidden skill paths.
- Check that an explicit standing direction is retained with its scope, while an inferred generalisation remains a proposal until the user confirms it.
- Given recurring friction, observe whether reflection selects a proportionate improvement and updates only the appropriate canonical homes. With no warranted change, verify that it invents neither edits nor a checkpoint.
- During an upgrade, preserve existing user principles and local skill adaptations; resolve conflicts rather than overwrite them.

Record the host, loading method and observed results. Static packaging checks do not establish agent compliance or automatic skill discovery.
