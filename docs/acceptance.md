# Installation acceptance, not a leaderboard

These preserve the original A1–A7 properties. Adapt the mechanism, not the property. This is ordinary installation verification, not a comparative evaluation campaign. Record implementation, host and conditions; a documented rule is not a pass.

Inject faults only into disposable synthetic copies, never a real person's brain. A1/A7 require a session that did not perform the setup/change and has no original chat history. A compaction or fork containing expected answers is not that check. Without such a session, report **not run**.

| Check | Required observation | Git/Markdown procedure |
|---|---|---|
| **A1: action-ready start** | Files-only purpose/current work, all human-waiting threads, next action or exact decision, within the local budget | Run installed resume; compare against source records, not only the index |
| **A2: current vs history** | Current state distinct; dated supersession; history cannot masquerade as current instruction | Inspect topic status and newest-first history directly; kb.py does not enforce their order |
| **A3: discovery** | Knowledge findable without its cockpit entry; origin/change traceable | Find a thread fact through Map.md, then its outcome/history |
| **A4: evidence/focus** | Evidence dates not save dates; sourced goal, labelled inference and honest unknowns | Compare every live thread and Focus with dated sources; a checker cannot prove truth |
| **A5: coherent persistence** | Related knowledge, navigation/index and outcome persist together; partial updates exposed | In a disposable committed copy stage a topic without CHANGELOG.md: `check --staged` fails. Also leave a linked topic untracked or its Map entry unstaged: prospective-commit validation must fail despite a valid working-tree view. Stage the complete real update, check and commit once; inspect the saved commit. The checker establishes structure, not meaningful outcome content |
| **A6: structural drift** | Broken references, duplicate navigation and budget overflow detected | In a clean disposable copy add [[Nowhere]] and a thirteenth thread: check names both. Use equivalent faults for other layouts |
| **A7: unfinished work** | A fresh session reports/preserves another writer's incomplete update, without sweeping it into its commit or discarding it | Leave a topic edit uncommitted in a clone; another session resumes. Verify no commit/reset/stash/discard |

For non-Git implementations, declare the A5/A7 mechanism and test. File readback alone does not prove transactions or recovery. A6 numbers/headings belong only to the reference; other budgets get their corresponding boundary tests.

## Additional use-driven checks

- For an adopted operating gate, verify its complete block is first in every applicable AGENTS.md / CLAUDE.md, before titles/imports, and mirrors match the declared local authoritative copy: compare each complete opening-to-closing tag span, not just the four labels. Preserve other instructions and record any deliberate placement/wording adaptation. Verify the actual host loading path, including explicit startup reads when needed; do not load the full contract twice. Report any duplicate gate exposure and unverified host behaviour. File inspection alone is not a loading/compliance test.
- Observe the gate through task outcomes, not recital: connection to the user's goal, grounded action, proportionate handling of recurring friction, and safe preservation of continuity before compaction. Check for added ceremony or unnecessary work too. Do not ask for private reasoning or infer effectiveness from a checklist in a reply. Comparative benefit requires a controlled with/without evaluation; this installation check does not establish it.
- A narrative deferred decision becomes actionable with decision-maker and reopening condition.
- A durable lesson is found/applied before the first relevant action after restart.
- A superseding instruction retains scope: valid conditional permission enables progress when conditions hold and prevents the prohibited branch otherwise.
- With multiple writers, the agent honours refused acquisition and unknown ownership. See [shared writers](shared-writers.md); helper tests alone are insufficient.

Record **pass / fail / not run / adapted with observed equivalent** per check. Exercise applicable checks successfully before claiming full acceptance. Reduced verification stays visible; useful partial operation is not universal validation.

## v0.2 reference verification

On the development macOS host, `python3 -m py_compile examples/git-markdown/tools/kb.py` passed and `python3 -m unittest discover -s tests -v` ran 45 synthetic helper tests: 44 passed; the non-UTF-8 filename test was skipped because the filesystem refuses to create that filename. The suite covers working-tree/prospective-commit differences, structural drift, ordinary-file boundaries and cooperative lock/refusal behaviour in disposable Git repos. It does not install into existing personal memories.

Fresh-agent A1/A7, live concurrent-agent compliance, host-entrypoint compatibility and reduced human burden have **not been established** by this revision. These helper results are not a full installation acceptance or a comparative evaluation result.
