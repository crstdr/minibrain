# Preserve capabilities; improve a named failure

Start from the original operating contract, not a tiny layout that postpones safeguards. The [contract](../starter/instructions.md) owns the rules. These are illustrative choices, not mandatory stages.

| Observed failure | Candidate change | Verify afterward |
|---|---|---|
| Startup buries live decisions | Separate bounded index from subject detail/history; adapt the local budget | Fresh session finds every decision, condition and source |
| Facts vanish when threads close | Give knowledge an independently discoverable home | Find it without the old cockpit entry |
| Saved lesson is ignored before action | Put its trigger/pointer on the action path; inspect the failed decision process | Applied before the first attempt |
| Narrative has decisions absent from actionable state | Check capture against unresolved choices just discussed | No silent omission; longer readback alone is not the fix |
| A newer instruction competes with an old rule | Supersede old scope; retain new conditions | Act on the applicable rule and evidence |
| Changes cannot be traced/recovered | Reuse suitable versioning/backups and coherent updates | Inspect changes and exercise recovery on disposable data |
| Writers collide | Apply adequate coordination, including a shared Git staging index where present | Refused acquisition stops the agent; no overlapping protected writes |
| A small subject now needs multiple notes or attachments | Promote its memory space from a note to an indexed folder; preserve ownership and incoming links | Old references still resolve or explicitly redirect; no lost facts, decisions or evidence |
| Retrieval misses relevant knowledge | Improve pointers first, then permitted search/storage | Useful context without noise or authority confusion |
| Archive upkeep has little benefit | Inspect retrieval needs and required traceability; consolidate | Preserve useful knowledge with less maintenance |

A reference's 150-line / 12-thread budget is a starting choice, not universal. The obligation to bound startup and expose overflow remains.

Recurring cap pressure is a reason to step back: is the index carrying history, is navigation failing, or is the budget wrong for the work? Do not merely trim forever or raise the cap to silence a check. Record any user-delegated maintenance authority, its limits and required verification in the local instructions. If budget adjustments are already authorised, change the local rule and corresponding checker together and verify that startup still exposes current responsibilities within a useful budget. Otherwise propose the change. Delegation is not permission to discard history, weaken safeguards or bypass the restructuring rule below.

The [memory-space pattern](spaces.md) lets the same purpose/current-state/navigation structure recur without copying root instructions or creating a cockpit in every folder. It is an option when growth names a real need, not a schedule for splitting files.

Before consequential restructuring, propose source ownership, where material moves and how entrypoints change. Preserve the user's opportunity to respond. Do not migrate a working system to match an example tree.

Handoffs cite canonical records through authorised communication; they do not require per-writer memory or durable handoff inboxes. Retain unfinished work and procedures outside host continuation notes.

Sync, history and external stores bring conflict, access and deletion questions. Declare dependencies when moving hosts. A local writer lock does not coordinate separate clones or make remote services private.
