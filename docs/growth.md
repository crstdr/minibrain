# Grow only to solve a real problem

The starting instance is `MINIBRAIN.md` plus `MEMORY.md`. These are options, not maturity levels everyone must reach.

| Observed problem | Smallest plausible change | Verify afterward |
|---|---|---|
| Startup reading buries current work | Extract a coherent subject into a topic; keep a short pointer | A fresh session finds purpose, live decisions and the relevant detail |
| Several topics become hard to navigate | Add an index with one canonical entry per topic | Links resolve; no competing copies of the same fact |
| Decisions cannot be traced or recovered | Use an existing version-control or backup workflow | Read back a change and demonstrate recovery on disposable data |
| A correct note is not found when needed | Improve task-facing pointers first; then assess permitted search tools | A previously missed case now retrieves the right context without extra noise |
| Two agents need to contribute | Keep one writer and scoped, source-backed handoffs first | No duplicate work, lost updates or ambiguous authority |
| Single-writer handoff is a measured bottleneck | Evaluate an existing transactional store or explicit writer-lock workflow | Contention and interrupted writes are tested before real overlap |
| A file is the wrong home for a large dataset | Use a permitted external store with clear source-of-truth boundaries | Export, access control, deletion and restore work—not just ingestion |

For a restructuring, identify what each source will own, where old material goes and how readers find it. Preserve actionable state and meaningful corrections. Let the user weigh consequential changes; do not ask them to supervise every typo.

Git or remote sync can add recovery and sharing, but also exposure and conflict. Never publish a real brain because the product repository is public. Memory portability includes purpose, pending responsibilities and learned procedures—not only files or a biography. Dependencies and access permissions must be declared when moving hosts.

There are no universal line limits here. Use reading cost, retrieval failures, information sensitivity and actual workload to decide when growth pays for itself. Neither endlessly accumulating history nor endlessly archiving it is the objective.
